# Text editing audit, 2026-11-22

Scope: the text editing fundamentals of Grassfield Notes 1.0.0 (egui 0.37 / eframe 0.37, `origin/main` 2daf1c8), measured
against Apple Notes on macOS 27 as the model and Bear, Obsidian and Craft as the polish bar. Trigger: the owner could not
copy and paste text (reported 2026-11-22). Sources read: `src/app/editor.rs`, `src/app/files.rs`, `src/app.rs`,
`src/markdown.rs`, `Cargo.toml`, and the egui / egui-winit / eframe 0.37.0 sources from the lock file. Line numbers are
those of branch `fix/clipboard-and-audit` after the fixes below, unless they name an upstream crate.

Priorities: **P0** broken basics, **P1** expected by a pro user, **P2** polish.

## Root cause of the copy and paste report

`Cargo.toml` turned eframe's default features off and listed `glow`, `default_fonts`, `x11` and `wayland`, but not
`clipboard`. eframe forwards `clipboard` to egui-winit's `clipboard` feature (`eframe-0.37.0/Cargo.toml`, `[features]`),
which is the only thing that pulls in `smithay-clipboard` (Wayland) and `arboard` (X11, and Wayland data-control). Without
it, `egui-winit-0.37.0/src/clipboard.rs` (`Clipboard::get` / `set_text`) falls back to a `String` kept inside the
process: Ctrl+C / Ctrl+X / Ctrl+V worked from one place in Notes to another, but nothing copied in Notes reached another
application and nothing copied in a browser or terminal could be pasted into Notes. `cargo tree -i smithay-clipboard`
printed "did not match any packages" before the fix.

Fixed: `Cargo.toml:19-22` adds `clipboard`. On Wayland egui-winit now reads and writes the clipboard through
smithay-clipboard on the window's own Wayland connection (the core `wl_data_device` protocol, so it works on every
compositor, Hyprland included), with arboard as the fallback; middle-click paste of the PRIMARY selection and
"selection settled" PRIMARY writes come with it (`egui-winit-0.37.0/src/lib.rs:887-895`, `:1244-1246`).

Nothing in the app swallowed the keys: egui-winit turns Ctrl+C/X/V into `Event::Copy/Cut/Paste` before any key event
exists (`egui-winit-0.37.0/src/lib.rs:1129-1153`), and no `consume_shortcut` in `src/app.rs:910-945`,
`src/app/editor.rs` or `src/app/files.rs` uses plain Ctrl+A/C/V/X/Y/Z (regression test
`app::textedit::tests::the_app_never_takes_the_clipboard_or_editing_chords`).

### Checked and fine

- Selection: double-click selects a word, triple-click a line, shift-click and drag extend by character, word or line
  (`egui-0.37.0/src/text_selection/text_cursor_state.rs:151-200`); Shift+arrows select; Ctrl+Left/Right move by word and
  Ctrl+Backspace/Delete delete words (`cursor_range.rs:283-300`, `builder.rs:1573-1594`), which Grassfield's Alt+arrows
  and Alt+Backspace send (`forwarding.lua`); Home/End and Ctrl+Home/End (Super+arrows) move to the line and document
  ends; Ctrl+A selects all.
- Undo / redo keys: Ctrl+Z, Ctrl+Shift+Z and Ctrl+Y in every text field (`builder.rs:1341-1370`).
- Keyboard layouts: egui-winit matches shortcuts on the logical key, falling back to the physical key, so Ctrl+Z / A /
  C / V work on AZERTY (`egui-winit-0.37.0/src/lib.rs:1124-1129`).
- IME, dead keys and compose: winit 0.30 handles xkb compose and text-input-v3 on Wayland; TextEdit consumes the IME
  events. Typing é, è, ç, à, ù and ê through dead keys was NOT verified live (see the report).
- HiDPI: winit uses wp_fractional_scale_v1, egui lays out in points; crispness at 1.25 NOT verified visually here.
- Links: Ctrl+click opens `[[wiki links]]`, `#tags` and web links (`editor.rs:584-596`, `follow_link`), web links only
  after showing the address.
